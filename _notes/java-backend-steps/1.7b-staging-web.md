# 1.7b Staging web environment

**Status:** ◐ In progress (2026-11-19) · Phase 1 · cross-cutting context in [0.0a.java-backend-plan.md](0.0a.java-backend-plan.md)

**Task:** give staging its own deployed web app, completing the baseline's "Neon branch + server instance + Vercel environment". 1.8 (OAuth round-trips on staging) and 1.9 (cookies from the staging web origin) depend on it.

**Why a separate Vercel project:** Root Directory is a project-wide setting. `main` still has the web app at the repo root and `feature/server` has it in `client/web`, so changing the prod project would break prod deploys from `main` (that change stays deferred with 0.1). A second project leaves prod untouched.

**DoD:** the staging URL asks for the staging password; behind it, credentials login works against the staging Neon branch; a link mailed by the Java staging server opens the staging web app.

## Done

- **Password gate** (`client/web/lib/stagingGate.ts` + top of `middleware.ts`): HTTP Basic auth on every route when `STAGING_PASSWORD` is set; no-op when unset, so prod is unaffected. Username ignored, constant-time compare, UTF-8 passwords. 6 Jest tests. Static assets (`_next`, files with extensions) and the `/relay-cq` analytics proxy are outside the middleware matcher and stay ungated.
- **Fly staging scaled to one machine** (`flyctl scale count 1`), so the in-memory per-IP rate limits mean what they say (the 1.6 follow-up).

- **Vercel project `circadium-staging`** (team `circadium-team`, set up with the Vercel CLI 2026-11-19): `https://circadium-staging.vercel.app`.
  - Root Directory `client/web`, framework Next.js, Node 24.x (matches prod), Git-connected to `marcusryden92/circadium` with **Production Branch `feature/server`**, so every push to the branch deploys staging. The build command comes from `client/web/vercel.json`, whose `prisma migrate deploy` on production builds now applies pending migrations to the staging Neon branch automatically.
  - Deployment protection matches prod (`prod_deployment_urls_and_all_previews`): Vercel login guards previews and per-deployment URLs; the `circadium-staging.vercel.app` domain is guarded by the app's own `STAGING_PASSWORD` gate.
  - Production env vars: `DATABASE_URL`, `DIRECT_URL`, `NEXTAUTH_SECRET`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `RESEND_API_KEY` copied from `client/web/.env.staging` as **sensitive** (write-only); `STAGING_PASSWORD` newly generated (sensitive); `NEXT_PUBLIC_APP_URL=https://circadium-staging.vercel.app` (plain). Deliberately not copied: `ANTHROPIC_API_KEY` (unused, the assistant is BYOK) and the empty GitHub keys (GitHub login is off on staging). Database hosts checked: staging `ep-dawn-glitter`, prod `ep-summer-feather`.
  - `.env.staging` keeps `NEXT_PUBLIC_APP_URL=http://localhost:3000`: it is for running the web locally against staging.
- **Fly `WEB_BASE_URL`** → `https://circadium-staging.vercel.app`, so links mailed by the Java staging server open the staging web.

- **Moved to `staging.circadium.app` in 1.9 (2026-11-20)**: cookies cannot be shared between `vercel.app` and `fly.dev` (both public suffixes), so staging web and API now run at `staging.circadium.app` / `api.staging.circadium.app`, with the Google redirect URIs registered for the new hosts. See [1.9](1.9-web-cookie-model.md#staging-2026-11-20).

## Follow-ups

- **Prod project previews would use the prod database.** The prod `circadium` project scopes `DATABASE_URL` (and most other vars) to production + preview + development. Previews of `feature/server` fail today only because that project's Root Directory is still the repo root. When 0.1 moves it to `client/web`, every preview build of the prod project would connect to the prod Neon branch. Before that, restrict prod's `DATABASE_URL`/`DIRECT_URL` to production, or point preview at a separate branch.

- **Mail abuse via the open staging API:** the Java staging server on `fly.dev` is not behind the web gate and sends real mail. Rate limits bound it today. Staging has its own Resend key since 2026-11-20 (sending-only, `circadium.app`; set on Fly, the Vercel staging project and `.env.staging`), so it can be revoked without touching prod. Still to do: a `circadium.mail.allowed-recipients` allowlist so staging only mails your own addresses.
- **Gating the Java API** would need a staging-only custom header (for example `X-Staging-Key`) checked in `RateLimitFilter`; Basic auth cannot be used there because `Authorization` carries the bearer token.
- When the branch merges (0.1), decide whether staging keeps its own project or becomes the prod project's preview environment.

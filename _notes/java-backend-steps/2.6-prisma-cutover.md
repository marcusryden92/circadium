# 2.6 Prisma cutover: Flyway owns the schema, web loses Prisma

**Status:** ✓ DONE 2026-11-25 — in prod the same evening (PR #27, merge b64ae300): both CIs
green on main, Fly prod deployed with Flyway baseline+V2 applied (verified on the prod DB:
columns timestamp(3), all 277 SimpleEvents rows intact through the cast, _prisma_migrations
gone), Vercel prod Ready, www.circadium.app answering. One CI-caught fixup (d3f65f23:
WeekDayType re-export + session test fixtures — a stale local tsbuildinfo had masked both).
**PHASE 2 COMPLETE: the web has zero server actions and zero Prisma.** ·
cross-cutting context in [0.0a.java-backend-plan.md](0.0a.java-backend-plan.md)

**Decisions taken during implementation (supersede the plan below where they differ):**

- **The SimpleEvents migration is Flyway `V2`, not a last Prisma migration.** A Prisma
  migration would force two sequenced pushes with intermediate web states (migration deploy
  via Vercel first, cutover second). Instead `V1__baseline.sql` IS the schema as the last
  Prisma migration left it, `V2__simple_event_times_timestamp.sql` carries the TEXT →
  `timestamp(3)` change + the `("userId","start")` index + drops `_prisma_migrations`, and
  the SAME server deploy that expects the new types applies them at boot (Flyway runs before
  the health check, blue-green safe). `baseline-on-migrate` stamps the Prisma-built
  staging/prod/local DBs at V1 on first contact.
- **Tests build their schema from the Flyway migrations** — `withInitScript(db/schema.sql)`
  and the dump itself are gone; a drifted migration now fails every integration test.
- **The seed is a compact Java `DemoSeeder`** (local profile, `circadium.seed.enabled`),
  not a literal port of the ~1,200-line TS generators: same conventions (rolled-up goal
  durations, `(i+1)*1024` sibling keys, root-only categoryId, admin upsert semantics), a
  leaner representative dataset. The TS generators live on in git history if ever wanted.
- **Deploy window note:** between V2 applying (new server boot) and the old machine
  retiring, the OLD server reads timestamp columns as strings (`2026-01-01 10:00:00`
  shape) in its bootstrap. Minutes long, single-user prod, deploy at a quiet moment.

**Task:** delete `prisma/`, the generated client, the driver adapter, and the conformance
asserts; `flyway baseline` on the current schema — Flyway owns migrations from now; port
the seed to Java. **Rides along as the last Prisma migration:** `SimpleEvents.start/end`
TEXT → `timestamp(3)` + the scan index (the 2.5 audit decision).

**DoD:** `client/web` has zero server actions and zero Prisma; a fresh `flyway migrate` +
seed stands up a working local environment.

## Recon (2026-11-25)

### What still touches Prisma at runtime (small)

- `lib/db.ts` — the PrismaClient singleton (PrismaPg adapter).
- `lib/session/session.ts` `getSession` — the real work: per-request DB check (user
  fields, `sessions` family liveness, `passwordChangedAt` vs token `iat`, providers).
  Java's `GET /auth/me` is token-echo only (no DB), so the cutover needs a DB-checked
  session endpoint on Java carrying the user fields + `onboardedAt`/`aiMode`/`aiModel`.
- `app/(protected)/layout.tsx` — reads `onboardedAt`/`aiMode`/`aiModel`; rides the same
  new endpoint (ProfileController has only write endpoints).
- `data/user.ts` — ZERO callers since the auth flip; delete.
- `AiMode` imported AS A VALUE in 4 files (AiAccessContext, AISection, OnboardingAIStep,
  lib/api/profile); shared contracts do NOT have AiMode yet — add it (type + const).

### Types are already solved

`@circadium/shared/contracts` holds hand-declared row types + enums, and
`types/contractConformance.ts` exists purely to prove them faithful to the Prisma
payloads. Cutover = `types/prisma.ts` re-exports the shared contracts (keeping its
runtime augmentations), asserts deleted. No type rewrite.

### Migration/deploy machinery today

- Prod migrations: Vercel production `buildCommand` runs `prisma migrate deploy`
  (vercel.json) — this step moves migration execution to Flyway on the Java deploy and
  drops the Vercel step.
- Server integration tests: Testcontainers `withInitScript("db/schema.sql")` — a 993-line
  dumped schema. Post-cutover that dump becomes the Flyway `V1__baseline.sql` (one
  source; tests can keep the initScript pattern pointed at the baseline or run Flyway).
- Flyway is already on the classpath, disabled (`spring.flyway.enabled=false`).
- Seed: `prisma/seed.ts` + `seed-helpers/` ≈ 1,200 lines of generator logic
  (categories/locations+travel/planners/plans/templates) + `clear-data.ts`.

## Plan

### Stage A — the last Prisma migration (SimpleEvents timestamps)

1. Prisma migration: `start`/`end` `USING ::timestamp(3)` + index `("userId", "start")`.
2. Java: `SimpleEventEntity` String → Instant; sync writer `Column.timestamp()`;
   bootstrap wire stays `.SSS'Z'` ISO (1.13b Jackson precedent); fixtures/corpus;
   `.\mvnw.cmd verify`.
3. Web: `types/prisma.ts` re-types start/end (WithIsoTimestamps pattern extension);
   type-check + Jest.
4. Refresh `db/schema.sql`; staging deploy + migration, then prod.

### Stage B — the session read moves to Java

5. `GET /auth/session`: DB-checked (family alive, passwordChangedAt) → user fields +
   providers + `onboardedAt`/`aiMode`/`aiModel`; integration tests.
6. Web: `getSession` + the protected layout call it (cookie forwarded server-side);
   delete `data/user.ts`.

### Stage C — cutover

7. `types/prisma.ts` → shared-contract re-exports; AiMode value const into shared;
   delete `contractConformance.ts`.
8. Delete `prisma/`, `generated/`, `lib/db.ts`, prisma deps + scripts + postinstall,
   Vercel buildCommand prisma step.
9. Flyway: `V1__baseline.sql` from the schema dump; enable with
   `baseline-on-migrate` (existing DBs baseline at V1, fresh DBs build from it).
10. Seed → Java (dev-profile seeder; port of the TS generators).
11. CI + CLAUDE.md updates (web, server, root). Staging bake → main → prod.

## Decisions taken en route

- The SimpleEvents timestamp migration rides HERE (not 2.5): audit 2026-11-25 found the
  column uniformly clean on prod + staging; doing it under Prisma keeps the web re-typing
  and the conformance asserts alive for one coordinated change before they die.
- The dirty `Planners` datetime columns (deadline/starts/earliestStartDate: date-only +
  local-offset rows) are OUT of scope — they need a normalizing rewrite, own pass, post-2.6
  (via Flyway).

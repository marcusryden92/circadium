### What was built

- **Schema**: two Prisma migrations: `add_sessions_table` plus `add_sessions_family_id`, which adds `familyId` (+ index). Every rotation copies the family id forward, so chain revocation is one `delete where familyId = ?`, and only the affected device is logged out.
- **`auth/AuthProperties`**: `circadium.auth.*` (issuer, audience, TTLs, `allow-ephemeral-key`, `signing-keys[n].{kid,private-key}`).
- **`auth/SigningKeys`**: the RS256 key ring. Parses PKCS#8 PEM and derives the public key from the CRT private key (one secret per key). Index 0 signs; all keys verify and are published. With no keys it generates an ephemeral one in `local` and fails startup everywhere else.
- **`auth/JwtConfig`**: `NimbusJwtEncoder` + `NimbusJwtDecoder.withJwkSource` (local key ring, no self-HTTP fetch) with timestamp + issuer + `JwtAudienceValidator`.
- **`auth/TokenService`**: `startSession` (for 1.6/1.8 login flows), `refresh` (pessimistic row lock, reuse → delete family; `noRollbackFor` so the revocation commits while the request still 401s), `logout` (idempotent family delete), `revokeAllSessions`. Access JWT claims: `iss sub aud iat exp jti role sid` (`sid` = familyId). Refresh tokens: 32 bytes `SecureRandom`, base64url, stored as SHA-256 hex.
- **`auth/AuthController`**: `POST /auth/refresh`, `POST /auth/logout` (body-based for now), `GET /auth/me` (probe), `GET /.well-known/jwks.json` (5-min public cache). All invalid refresh cases answer the same 401 ProblemDetail.
- **`config/SecurityConfig`**: stateless resource-server chain (see `server/CLAUDE.md` "Security"). **`config/ClockConfig`**: shared `Clock` bean.
- `ErrorHandlingIntegrationTest` moved from `httpBasic` to the `jwt()` post-processor (the default chain + generated user are gone).

### Design decisions

- **Sliding refresh expiry.** Each rotation gets a fresh 30 days, so an active device stays logged in indefinitely. Add an absolute family cap later if wanted (would need a `familyCreatedAt` or reading the oldest row).
- **No concurrency grace window.** Two tabs refreshing the same token simultaneously look like reuse and revoke the family. Revisit in 1.9 (the web cookie model can serialize refreshes) or add a few-second grace keyed on `replacedBy` + `lastUsedAt`.
- **Logout does not kill the access token**; it lives out its ≤15 min. No per-request DB lookup, by design.

### Staging deploy (2026-11-19)

- Neon staging: `add_sessions_table` + `add_sessions_family_id` applied via `prisma migrate deploy` (credentials in the gitignored `client/web/.env.staging`).
- Fly secrets: `AUTH_ISSUER=https://circadium-server-staging.fly.dev`, signing key `kid=staging-2026-11` (2048-bit, generated locally, imported with `fly secrets import`, local copy deleted; the private key exists only in Fly). Rotating it: generate a new key, import it at index 0, move the old one to index 1, deploy, drop index 1 after 15 minutes.
- Smoke on `https://circadium-server-staging.fly.dev`: health UP; JWKS serves one RS256 key with no private parts and a 5-min public cache; `/auth/me` without a token and with a malformed token both 401 with `WWW-Authenticate`; unknown refresh token 401 ProblemDetail with `requestId`; `/v3/api-docs` 401 (admin-only off `local`).
- Fixed during the smoke: `GlobalExceptionHandler` skipped `requestId` for `ErrorResponseException`s (Spring passes a null body there; the advice now falls back to the exception's own ProblemDetail), and staging/prod set `server.forward-headers-strategy: native` so generated URLs use Fly's `https` scheme.

### Follow-ups (not blocking)

- `/actuator/prometheus` and `/metrics` now require a JWT; scraping needs its own auth when metrics collection is set up.
- Security-layer 401s (missing/bad bearer) return an empty body with `WWW-Authenticate`, not a ProblemDetail. Add a ProblemDetail entry point if clients need a uniform error shape.
- Token cleanup job (`SessionRepository.deleteAllExpiredBefore`) belongs in `jobs/` with ShedLock (Phase 2).
- Audit-log rows for reuse detection arrive with the audit table in 1.6; today it is a `WARN` log line.

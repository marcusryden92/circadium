# 1.7b Staging web environment

**Status:** ◐ In progress (2026-11-19) · Phase 1 · cross-cutting context in [0.0a.java-backend-plan.md](0.0a.java-backend-plan.md)

**Task:** give staging its own deployed web app, completing the baseline's "Neon branch + server instance + Vercel environment". 1.8 (OAuth round-trips on staging) and 1.9 (cookies from the staging web origin) depend on it.

**Why a separate Vercel project:** Root Directory is a project-wide setting. `main` still has the web app at the repo root and `feature/server` has it in `client/web`, so changing the prod project would break prod deploys from `main` (that change stays deferred with 0.1). A second project leaves prod untouched.

**DoD:** the staging URL asks for the staging password; behind it, credentials login works against the staging Neon branch; a link mailed by the Java staging server opens the staging web app.

## Done

- **Password gate** (`client/web/lib/stagingGate.ts` + top of `middleware.ts`): HTTP Basic auth on every route when `STAGING_PASSWORD` is set; no-op when unset, so prod is unaffected. Username ignored, constant-time compare, UTF-8 passwords. 6 Jest tests. Static assets (`_next`, files with extensions) and the `/relay-cq` analytics proxy are outside the middleware matcher and stay ungated.
- **Fly staging scaled to one machine** (`flyctl scale count 1`), so the in-memory per-IP rate limits mean what they say (the 1.6 follow-up).

## Follow-ups

- **Mail abuse via the open staging API:** the Java staging server on `fly.dev` is not behind the web gate and sends real mail. Rate limits bound it today. Later: a separate Resend API key for staging (revocable on its own) and a `circadium.mail.allowed-recipients` allowlist so staging only mails your own addresses.
- **Gating the Java API** would need a staging-only custom header (for example `X-Staging-Key`) checked in `RateLimitFilter`; Basic auth cannot be used there because `Authorization` carries the bearer token.
- When the branch merges (0.1), decide whether staging keeps its own project or becomes the prod project's preview environment.

## What was built

`client/shared/src/calendar-core/layout/` -- the layout module for the own calendar
renderer. Framework-free TS, no React, no FullCalendar imports in production code.

### layout/ (rewritten with date-fns)

1. **visibleRange.ts** -- `computeVisibleRange(anchor, firstDay, dayCount)` snaps to the
   containing week and returns a CalendarRange; `enumerateDays` enumerates the range as
   midnight Dates.

2. **daySlice.ts** -- `sliceEventIntoDays(start, end, visibleRange)` cuts an event's time
   range into per-day-column `DaySlice` segments. Events spanning midnight are split
   (overnight split); slices clipped to the visible range carry
   `isOvernightContinuation: true`.

3. **timeGrid.ts** -- pure arithmetic from hourHeight:
   - `minutesToPx` / `pxToMinutes` -- the time-to-pixel conversion pair.
   - `snapMinutes` / `snapPx` -- snap to a grid increment.
   - `dateToMinutes` -- Date to minutes-from-midnight.
   - `dayColumnHeight` -- 24h column height.

4. **hitTest.ts** -- `hitTest(x, y, columnWidth, hourHeight, visibleRange, snapMin)` maps
   a pixel coordinate to a day + minute, with optional snap.

5. **segmentGeometry.ts** -- the top-level layout entry points:
   - `layoutEvents(events, range, hourHeight, comparator, eventMinHeight)` -- slices,
     groups by day, runs placement, returns `TileGeometry[]`.
   - `layoutDay(segs, hourHeight, eventMinHeight)` -- placement for a single day's
     pre-sliced segments.
   - `TileGeometry` carries top/height in px, left/width as 0-1 fractions.
   - `SegmentComparator` parameter replaces FullCalendar's hardcoded `-duration,start`.

### layout/placement/ (ported from FullCalendar v6.1.21, MIT)

Every file in this folder has a header naming FullCalendar, the version, and
"Copyright (c) 2021 Adam Shaw"; the full MIT license text is in `LICENSE.md`.

**Ported to TS (pure numeric-span code):**
- `segHierarchy.ts` -- `SegHierarchy` class + `groupIntersectingEntries` (from
  core/internal-common.js ~L5901-6089).
- `utils.ts` -- `binarySearch`, `insertAt`, `intersectSpans`, `joinSpans`,
  `getEntrySpanEnd`, `buildEntryKey` (core/internal-common.js ~L6060-6133).
- `web.ts` -- `buildPositioning`, `buildWeb`, `buildNodes`, `findNextLevelSegs`,
  `stretchWeb`, `webToRects`, `cacheable` (timegrid/internal.js L507-643). Outputs
  `{levelCoord, thickness}` as 0-1 fractions = CSS left/width.
- `types.ts` -- shared interfaces (Span, SegEntry, SegRect, WebNode, etc.).

**Rewritten (from hourHeight, no DOM measurement):**
- `placement.ts` -- `computeSegVCoords` and `computeFgSegPlacements` (timegrid/internal.js
  L645-690). FullCalendar measures DOM slat elements; ours computes from hourHeight.

About 370 lines of FullCalendar code ported; all in layout/placement/.

## Parity fixtures

9 scenarios generated by driving FullCalendar's own SegHierarchy + buildPositioning via a
one-off script (`generateFixtures.ts`). The committed `fixtures.json` is the source of
truth so parity outlives FullCalendar's removal in C.6.

| Scenario | Description |
|---|---|
| no_overlap | 3 non-overlapping events, all get full width |
| two_partial_overlap | 2 events overlap 50%, each 0.5 width |
| three_deep_nesting | 3 nested events, each 1/3 width |
| identical_start_end | 3 events with same start/end, each 1/3 width |
| dense_cluster | 6 staggered events, 4-deep at peak |
| zero_duration | Zero-duration event alongside a normal one |
| back_to_back | 3 adjacent non-overlapping events, full width |
| overnight_split_segment | Simulates overlap pattern from an overnight split |
| strict_order | strictOrder mode forces all entries to stack sequentially |

All 9 parity tests pass. Total: 48 layout tests.

## What C.3/C.4 should know

- `layoutEvents` takes a `SegmentComparator` -- the caller owns the sort order. No
  hardcoded eventOrder.
- `TileGeometry.left` / `TileGeometry.width` are 0-1 fractions, designed for
  `position: absolute` with percentage values (works in DOM and React Native).
- `TileGeometry.top` / `TileGeometry.height` are px from hourHeight.
- `hitTest` returns `{day, minute}` -- the interaction layer (C.3) maps pointer
  coordinates through this.
- `snapMinutes` clamps to [0, 1435] with 5-minute grid. The snap value is a parameter.
- Day slicing handles overnight splits and visible-range clipping; `isOvernightContinuation`
  lets the renderer style continuation segments differently.
- The barrel export is `calendar-core/layout.ts` (sibling file, same pattern as
  `calendar-core/model.ts`).
- `jest.config.ts` now excludes `generateFixtures.ts` from test discovery.

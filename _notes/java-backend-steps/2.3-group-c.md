## Implementation decisions (2026-11-24)

- **Layout:** `external/ics` (ical4j 4.1.1 parser + `IcsFeedFetcher`/`HttpIcsFeedFetcher` + `IcsUrls`),
  `external/googlecalendar` + `external/microsoftgraph` (interfaces + plain-RestClient impls on the
  shared `circadium.oauth` app registrations, pure `GoogleEventMapper`/`GraphEventMapper` pinned by
  the ported web tests), shared `external/ImportedCalendarEvent(+s)` (the occurrence-to-row finisher:
  end defaults, window overlap, deterministic id with exactly-3-fraction-digit ISO, dedupe, sort).
  Endpoints in `calendar/`: `ExternalCalendarController` (7 source endpoints),
  `CalendarIntegrationController` (status/calendars/sources/connection per provider),
  `CalendarOAuthController` (connect/callback), `DraftConversationController`,
  `ExternalCalendarErrorAdvice` (CalendarProviderException/IcsFeedException → 422
  provider_error/feed_error with the TS message strings verbatim as `detail`).
- **OAuth connect/callback are PUBLIC in the chain, cookie-authenticated by hand** (the chain's
  JSON 401 would dead-end a navigating browser, and the callback can arrive after the 15-minute
  access cookie lapsed mid-consent). Same `JwtDecoder` bean (session-family check included);
  signed-out → redirect to `WEB_BASE_URL`; everything else lands on the exact
  `/settings?{provider}=connected|error` shapes. State cookies
  `circadium_{google,microsoft}_calendar_state` (httpOnly, Lax, 600 s, path /). New redirect URIs
  `${AUTH_ISSUER}/integrations/{provider}/callback` must be registered with both providers.
- **Error contract:** statuses/codes are new (400 invalid_url, 404 calendar_not_found /
  location_not_found / conversation_not_found, 409 duplicate_source / not_connected, 422
  feed_error / provider_error / refresh_failed), but the `detail` strings are the TS error strings
  verbatim — the flip's client adapters map `problem.detail` back to the `{success:false, error}`
  shapes the UI consumes. The refresh failure carries the updated source (lastError written) as a
  `source` property on the ProblemDetail; its ErrorResponseException deliberately carries NO cause
  (the resolver would unwrap to the cause and hand it to the generic advice).
- **Deliberate deviations:** the ICS add parses before writing (kills the orphan-source wart);
  locationId ownership validated on patch/event-location (TS allowed any existing location id);
  a whole-feed ical4j parse failure salvages per-VEVENT block so a malformed rule still poisons
  only its own event (node-ical parity); network-failure fetch reads "The feed could not be
  fetched" for ICS and "Google/Microsoft could not be reached" for the providers (TS surfaced
  Node's raw "fetch failed"); no provider retries (TS had none); a UID-less VEVENT is silently
  skipped while the rest imports (TS failed the whole operation with a raw Prisma error); the
  provider display-name metadata lookup (reached only when the request carries no name) falls
  back to the calendar id on failure instead of failing the add; a fully UNconfigured OAuth
  connect redirects to `/settings?{provider}=error` instead of TS's 500 (half-configured guards
  on id+secret like TS); `IcsUrls.normalize` percent-encodes characters `java.net.URI` refuses
  (`|`/`^` encoded where WHATWG left them raw, path backslashes read as slashes) and keeps
  non-ASCII hosts un-punycoded — URL acceptance parity, not stored-string byte equality.
- **Parity-review fix round (2026-11-24, post-build):** the six-lane finder/skeptic workflow
  produced 25 findings; all fixed except the documented deviations above. Notables: `JsText`
  (calendar package) gives the draft-conversation id/title/sanitize paths and the external-name
  chains ECMAScript whitespace semantics (Java `trim`/`isBlank` classify NBSP/Zs/FEFF and
  C0 controls differently — different stored PKs and flipped "Untitled"/"Nothing to save"
  verdicts); IcsParser now follows node-ical's attached-override model exactly (overrides only
  consulted while an RRULE-bearing non-cancelled base expands — a cancelled base drops its live
  overrides, a non-recurring base ignores them, off-grid RECURRENCE-IDs never emit, RDATEs are
  stripped before `calculateRecurrenceSet` since node-ical expanded the rrule alone, empty
  SUMMARY stays ""); `HttpIcsFeedFetcher` bounds the WHOLE transfer at 15s via
  `sendAsync().get(15s)` (the JDK request timeout only covers status+headers) and follows
  scheme-downgrade redirects like fetch; `IcsUrls.normalize` replicates the WHATWG serialization
  (lowercase scheme/host, default-port strip, bare-authority "/", extended encode set);
  `toggleModeException` removes every duplicate copy; empty-string pagination tokens/nextLinks
  end pagination; empty-string OAuth tokens are refused with the contract strings; provider
  list-name fallbacks use JS truthiness, not `hasText`.
- **DraftConversations TEXT→timestamp(3)** migration (57th, applied on dev Neon) drops the
  `(now())::text` default — Java and the still-live action both stamp createdAt/updatedAt
  (UserViewStates pattern); entity flips String→Instant; `types/prisma.ts` re-declares via
  `WithIsoTimestamps`.
- **Flush discipline bugs the tests caught:** a JPA `save()` is invisible to plain-SQL statements
  in the same transaction until flushed — the source insert needed `saveAndFlush` before the
  events batch-insert (FK), the 50-cap trim needed it too (a 51st conversation survived), and the
  refresh event swap uses plain SQL on both sides (a deferred repository delete would collide with
  re-inserted ids). Also: test assertions on server-written timestamps must compare stored UTC
  wall-clock (`toLocalDateTime`), not `Timestamp.toInstant` through the JVM's zone.

**Task:** Move the external-calendar surface (ICS parse via ical4j with recurrence/overrides/EXDATEs; Google + Microsoft calendar connect/callback routes to Java; Microsoft rotating refresh tokens persisted every fetch; expansion window per refreshPolicy) and the draft-conversation history to the Java API, per the per-group loop.

## Server slice notes (2026-11-25)

- **Layout:** new `account/` (DataExportService, DataImportService, DataTransferController,
  ProfileController) + `feedback/` (FeedbackService/Controller) + `admin/`
  (AdminFeedbackController). SecurityConfig gates `/admin/**` with the API-docs adminWithMfa rule
  in EVERY profile (local included — it reads other users' data). `JsText` widened public.
- **Mail:** `EmailMessage` gained a nullable `replyTo` (Resend `reply_to`); `AccountMailer` gained
  `sendFeedbackNotification`; `MailProperties.supportAddress` (yml default support@circadium.app)
  is from AND to, reporter as reply-to.
- **Export:** JdbcTemplate per table, keys in Prisma model field order (the TS export's shape),
  timestamps as `.SSS'Z'`; deliberate deviations: stable `ORDER BY "id"` per table (TS left heap
  order), and windows only reachable through their category (TS parity — unassigned draft windows
  are not exported).
- **Import:** one multi-row `unnest` INSERT per table — Planners.linkedItemId and
  Categories.parentId are self-FKs checked at end of statement, so per-row inserts would refuse
  what Prisma's createMany accepted. Deliberate deviations from TS: the stale-JWT user-existence
  pre-check dropped (a Java token only validates while its sessions row exists); the TS
  `userId` spread into the TaskPreferences insert dropped (that table has no such column — latent
  in TS because the array was always empty); the committed import broadcasts the new dataVersion
  over the WS; `imported` still excludes the single-row viewState/preferences creates (TS parity).
- **Error contract:** TS strings verbatim as `detail` (support-message/suggestion validation, cap,
  import format/failed — the failed detail keeps the TS "Details: …" suffix). New codes:
  invalid_message, snapshot_failed, invalid_suggestion, suggestion_limit, invalid_vote,
  suggestion_not_found (deviation: a vote on a deleted suggestion is a clean 404 where TS leaked a
  raw FK error), report_not_found, invalid_payload, unrecognized_format, invalid_mode,
  import_failed, invalid_mode/invalid_model on the AI settings.
- **Parity fixture:** `src/test/resources/account/import-fixture.json` is a hand-written export in
  the TS shape; DataTransferIntegrationTest imports it (replace), re-exports, and compares section
  for section (NON_EXTENSIBLE), plus SQL-seeded pins for the never-imported sections (nested
  extendedProps, blob-free admin list, connections without refresh tokens, profile without
  password) and an add-mode remap test (placeId dedupe, rebuilt external ids, locationExceptions
  remap, dataVersion bump) and a rollback test.
- **DoD note:** the "byte-compare" wording resolves to NON_EXTENSIBLE JSON-tree comparison (byte
  equality was never real — TS row order was Postgres heap order). Real-world check at the flip:
  download a TS export from prod BEFORE deploying, a Java export after, and diff.

## Decisions (2026-11-25)

- **`actions/settings.ts` rides this group.** The plan's terse list doesn't name it, but 2.6
  requires zero server actions and no other group owns it. Three small writes: display name,
  `aiMode` (BYOK/OFF only — MANAGED reserved), `aiModel` (validated against the model lineup).
  The lineup lives in `web/lib/aiModels.ts`; the Java endpoint needs its own validation source —
  decide at implementation (mirror the id list in application config, or accept the web's
  validation and length-cap only; parity favors mirroring).
- **"Account deletion" in the master's Group D line is already done** — deletion moved to Java in
  1.7 and every Group D table cascades from `users` at the DB level (verify the FKs on
  FeedbackReports/Suggestions/SuggestionVotes at implementation; Prisma declares Cascade on all
  three). Nothing to port; check and tick.
- **The feedback email moves onto the existing Java Resend mailer** (`external/mail`, 1.7). The
  web's `lib/mail.ts` (support-mail-only since the auth flip) is deleted at the flip and
  `RESEND_API_KEY` leaves the web env (already a Fly secret for Java).
- **Per-group timestamp rule:** FeedbackReports/Suggestions/SuggestionVotes `createdAt` are TEXT
  with a `(now())::text` default — migrate to `timestamp(3)` in this step's Prisma migration,
  entity fields `Instant`, writer-stamped (UserViewStates pattern). The suggestion wall renders
  `createdAt` via `new Date(iso)`, so the ISO wire shape is unchanged.
- **Snapshot capture is internal service reuse:** `sendSupportMessage(includeSnapshot: true)`
  calls the export internally — on Java, FeedbackService calls the same DataExportService the
  export endpoint uses; never an HTTP hop.

## Recon (2026-11-25)

### feedback.ts — 5 actions, all live
- `sendSupportMessage({message, includeSnapshot})` → `{reportId}`. Zod `FeedbackMessageSchema`;
  snapshot = full `exportUserData()` blob stored ON the FeedbackReport row (only with consent);
  Resend notification to support@circadium.app with `replyTo` = user email — **email failure must
  not fail the action** (row is the source of truth; log and continue).
- `getSuggestions()` → `SuggestionView[]`: ALL users' suggestions, newest first, top 300.
  Per-row vote aggregation (upvotes/downvotes/score), `isMine`, `myVote` (sign of own vote),
  `authorName` (`user.name ?? "Anonymous"`).
- `createSuggestion({title, body?})`: Zod `SuggestionSchema`; 25-per-user cap (error string
  "You have reached the suggestion limit — delete one of yours to post a new one."); creates the
  row WITH a self-upvote (+1) in the same create — port as one transaction.
- `voteSuggestion(id, 1|-1|0)`: 0 deletes the vote row (deleteMany = idempotent); else upsert on
  the `[suggestionId, userId]` unique.
- `deleteSuggestion(id)`: own rows; an ADMIN session may delete any (`isAdminSession`).
  deleteMany semantics (missing = no-op).

### adminFeedback.ts — 4 actions, ADMIN-gated
- Gate: `role === "ADMIN" && twoFactorVerified`. Java equivalent exists — the token's `role`
  claim maps to `ROLE_ADMIN` and the Swagger mfa gate (1.15, SecurityConfig) checks the
  auth-methods claim; reuse that exact pattern for these endpoints.
- `listFeedbackReports()`: all reports, newest first, with user name+email; **snapshot blobs
  never ride the list** — presence resolved via a second id-only query (`dataSnapshot NOT NULL`).
- `getFeedbackReportSnapshot(id)` → the Json blob or null (non-object → null).
- `clearFeedbackSnapshot(id)`: null out `dataSnapshot` only (GDPR hygiene), keep the message.
- `deleteFeedbackReport(id)`: hard delete.
- Web consumers: `admin/feedback/page.tsx` + `hooks/useInspectionData.ts` (impersonation reads
  the same snapshot endpoint).

### dataExport.ts — one action
- 25 parallel queries → one JSON blob, `meta.format = "circadium.data-export.v1"`. **Secrets
  deliberately excluded:** profile is a field whitelist (no password hash), accounts are
  provider identity only, Google/Microsoft connections are `{email, createdAt, updatedAt}` only
  (never refresh tokens), token tables absent entirely.
- `taskPreferences` reach through the owning planner (`planner: {userId}`) — keyed by planner,
  not user.
- Key names are renamed in places (`simpleEvents` → `calendarEvents`, `templates` →
  `weeklyTemplates`, `draftConversations` → `aiConversations`) — the DoD byte-compare pins all
  of this.
- Used by: Settings DataSection (download) and sendSupportMessage (snapshot).

### dataImport.ts — one action, the big slice
- Modes: **replace** (wipe the account's rows children-before-parents — engine-derived rows go
  too, they rebuild; Google/Microsoft CONNECTION rows deliberately survive — then restore with
  ids preserved, re-owned to the current user) and **add** (every id remapped via a
  per-table-namespaced map; `skipDuplicates` on).
- Add-mode specials: locations dedupe by `[userId, placeId]` (existing row reused, mapped);
  external-event composite ids rebuilt as `${newSourceId}|${uid}|${start}`;
  `locationExceptions` JSON remapped by value; FK-less `parentId`/`linkedItemId` still remapped.
  Legacy habit `categoryId` stripped.
- Single-row state (viewState, schedulingPreferences) restored **only on replace** — add never
  clobbers current settings.
- Pre-check: the session user must exist in THIS database (stale-JWT-after-DB-migration guard,
  specific error string). One transaction, 120 s timeout. Ends with `dataVersion` increment.
- Dangling-reference filters: travelTimes need both locations, taskPreferences/members/
  dependencies/habitItems/completions need their planner/queue/habit to have resolved.
- Java port: this is the JdbcTemplate batch-insert hot path (sync-writer pattern), not JPA.
- **Size note:** an export with stored snapshots/years of data can be MBs. Check the request
  path end to end (Tomcat JSON body is not form-capped, but verify any explicit limits +
  compression on the response side) and set an explicit sane cap (e.g. 25 MB) with a clear 413.

### onboarding.ts + settings.ts — trivial
- `completeOnboarding()`: stamp `User.onboardedAt = now` (protected layout reads it server-side
  via Prisma — stays, it's a read; 2.6 owns reads).
- `settings({name})`: whitelist update of display name. `updateAiMode(BYOK|OFF)`,
  `updateAiModel(id validated against AI_MODELS)`.
- Consumers: OnboardingFlow, ProfileSection, AiAccessContext.

### Error contract
Same approach as Group C: statuses/codes are new, but user-facing `detail` strings verbatim from
the TS actions (suggestion cap, import format/stale-session/failure strings — note the import's
"Details: ${message}" suffix leaks internal messages; decide a Java-side equivalent that stays
honest without leaking SQL). Client adapters in `lib/api/` map ProblemDetail back to the
`{success, error}` shapes the UI consumes.

### Port design sketch (finalize at implementation)
- `POST /feedback/support` → `{reportId}`; `GET /suggestions`; `POST /suggestions`;
  `PUT /suggestions/{id}/vote`; `DELETE /suggestions/{id}`.
- Admin (ROLE_ADMIN + mfa, 1.15 gate pattern): `GET /admin/feedback-reports`,
  `GET /admin/feedback-reports/{id}/snapshot`, `DELETE .../{id}/snapshot`, `DELETE .../{id}`.
- `GET /account/export` (the blob, gzip rides 1.13's compression config);
  `POST /account/import` `{mode, data}`.
- `POST /account/onboarding-complete`; `PATCH /account/profile` `{name}`;
  `PATCH /account/ai` `{mode?, model?}`.
- New packages: `feedback/` (controller+service), export/import beside the sync writer (they
  share the bulk mindset), small additions to `auth/AccountController` or a new
  `account/ProfileController` for onboarding/profile/ai.
- Repositories: FeedbackReportRepository, SuggestionRepository, SuggestionVoteRepository are
  presumably bare/missing finders — add what the services need.
- Web flip: `lib/api/{feedback,adminFeedback,dataTransfer,onboarding,profile}.ts` (names TBD);
  delete the six action files + `lib/mail.ts` + `app/api/admin/route.ts` (and the `api/admin`
  mention in web CLAUDE.md); `RESEND_API_KEY` out of the web env (Vercel prod + staging).

## Web flip (2026-11-25)

- `lib/api/{feedback,adminFeedback,dataTransfer,profile}.ts` over `apiRequest`. Shape contracts
  preserved per consumer: feedback/admin adapters THROW (useServerAction and the catch-and-reload
  handlers consume `error.message` = the API's detail string); dataTransfer and profile keep the
  retired `{success, ...}/{error}` RESULT shape (DataSection, ProfileSection and AiAccessContext
  branch on it — AiAccessContext's saveKey would leak a throw out of its try block).
- Call sites switched: SupportCard, SuggestionWall, admin/feedback/page, useInspectionData,
  DataSection, OnboardingFlow, ProfileSection, AiAccessContext.
- Removed: the three Zod schemas only the actions parsed (Settings/FeedbackMessage/Suggestion),
  the `resend` dependency, and the actions' CLAUDE.md surface (plus the stale "prefer server
  actions" rule — there are no server actions left; Prisma reads in the protected layout remain
  until 2.6). `isAdminSession` stays in lib/auth.ts (the admin page's refusal copy + its test).

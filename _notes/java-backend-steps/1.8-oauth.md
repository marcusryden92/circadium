# 1.8 OAuth

**Status:** ☐ Not started · Phase 1 · cross-cutting context in [../java-backend-plan.md](../java-backend-plan.md)

**Task:** Google authorization-code with PKCE, `state`, exact redirect URIs; `Account`-table linking (existing rows keep working); web completion sets cookies; mobile completion mints a one-time 60s handoff code → `POST /auth/handoff`. Security checklist reviewed item-by-item (state entropy, code single-use, no token leakage in logs/referrers).

**DoD:** Google round-trips on staging; an existing OAuth user's account links, not duplicates.

**Decision (2026-11-19): GitHub login is dropped.** Unused (no users have signed up with it), so Java implements Google only. Removed from the web (NextAuth provider, login button, settings providers row, privacy page, env docs) and from the server's existing-account email wording.

**Follow-up:** iOS App Store guideline 4.8 requires Sign in with Apple (or an equivalent privacy-focused login) in an app that offers Google login; keep the provider mapping pluggable so Apple is config + one identity mapping when mobile ships.

**Reviewer note (2026-11-15):** before hand-rolling the code-exchange, evaluate letting Spring Security `oauth2-client` perform the provider dance (state/PKCE/redirect/token endpoint) and minting our own JWTs in the success handler — same token-model control, far less security-critical code to own and audit.

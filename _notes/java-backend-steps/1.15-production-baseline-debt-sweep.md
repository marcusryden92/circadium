# 1.15 Production-baseline debt sweep

**Status:** ◐ Code done 2026-11-23, not yet deployed. Came out of an antagonistic review of Phase 0–1: the per-step work was solid, but several cross-cutting promises in the master's "Production baseline" had no step that owned them and were never built. This step is their one owner. · Phase 1 · cross-cutting context in [0.0a.java-backend-plan.md](0.0a.java-backend-plan.md)

**Why a step at all:** these are not one feature, they are the baseline debt the numbered build walked past. Grouping them keeps the ask ("is the baseline actually met?") answerable instead of scattered across finished step files whose completion notes oversold.

**DoD:** `mvnw verify` green (new security-layer + WS + pong tests included); `pnpm -r type-check` + shared Jest green; staging bake, then the 1.13b two-session prod smoke; `NVD_API_KEY` repo secret set so the CVE job gates instead of skipping.

## Findings fixed

1. **1.13b insert-default was session-timezone, not UTC (the only prod-impacting bug).** The demuddle migration (`20261123120000`) gave the calendar tables `DEFAULT CURRENT_TIMESTAMP`, which casts into `timestamp(3)` through the **session** timezone; the update trigger already forced UTC. Java inserts omit `updatedAt`, so the default fires on every insert — correct in prod only because Fly/Neon run UTC, wrong on local dev (CET). Fix: new migration `20261123180000_utc_timestamp_defaults` sets every calendar default to `timezone('utc'::text, now())` to match the trigger; Prisma models use `@default(dbgenerated("timezone('utc'::text, now())"))`; the server test schema (`server/src/test/resources/db/schema.sql`) mirrors it on the ten calendar tables. The fix lives in the default expression, never in session state — staging/prod sit behind PgBouncer transaction pooling where `SET TIME ZONE` would not stick.

2. **Security-layer 401/403 bypassed ProblemDetail.** The filter chain (bad/absent token, CORS reject, and now the Swagger `amr` gate) runs before the DispatcherServlet, so `GlobalExceptionHandler` never saw it — the body was empty, falsifying 1.4's "RFC 7807 everywhere". Added `web/FilterProblemResponses` + `ProblemDetailAuthenticationEntryPoint` / `ProblemDetailAccessDeniedHandler` (wrapping Spring's bearer entry point/handler so `WWW-Authenticate` survives), wired into both the resource-server config and `exceptionHandling`; `ProblemDetailCorsProcessor` gives the CORS reject a body; `GlobalExceptionHandler` now maps `AccessDeniedException` (method-security 403 was otherwise the catch-all 500). Three new assertions in `ErrorHandlingIntegrationTest`.

3. **Swagger admin-gated by role only, not 2FA.** Every other admin surface requires `amr:mfa`; `/v3/api-docs` + Swagger UI took ADMIN alone, so a stolen password-only admin token read the schema. Now gated by an `AuthorizationManager` requiring `ROLE_ADMIN` AND `amr` containing `mfa`.

4. **Graceful shutdown absent.** `server.shutdown: graceful` + `spring.lifecycle.timeout-per-shutdown-phase: 75s` (above the 60s sync timeout); Fly `kill_timeout = "90s"` on both toml files, above the drain window — a deploy's SIGTERM now lets an in-flight sync commit.

5. **HikariCP never sized.** `spring.datasource.hikari.maximum-pool-size` (`DATABASE_POOL_SIZE`, default 10) + `minimum-idle`, a deliberate ceiling against Neon's connection budget. No session state set on the pool (PgBouncer).

6. **Account-flow tokens unhashed at rest.** Verification / password-reset / account-deletion tokens stored the raw uuid, unlike refresh tokens / handoff codes. New `auth/TokenHashing.sha256Hex`; `AccountTokens` stores the hash and returns the raw value (which exists only in the email); the three consumer services hash the presented token before lookup/delete. 2FA codes stay raw on purpose (a 6-digit space makes a hash no protection; online guessing is throttled by the login lockout). Tests updated to store hashes and assert against them.

7. **WebSocket zombie + registry leak.** The client heartbeat was send-only (a half-open socket left a tab silently deaf), and the registry never dropped a session whose send threw without a close callback. Server now answers the client ping with `{"type":"pong"}` (through the concurrency decorator), prunes the registry on send failure, and closes on transport error. Client (`realtimeClient.ts`) tracks one outstanding ping per interval and force-reconnects if a full interval brings no frame; any inbound frame (pong or dataVersion) resets it — this is the authoritative fix for the "deaf tab". (A server-side `ServletServerContainerFactoryBean` idle timeout was tried and dropped: it needs a real servlet WebSocket container, so it broke every MockMvc `@SpringBootTest`; the send-failure prune covers the registry regardless.) Tests: a server pong test, two client zombie/keep-alive tests.

8. **CVE scan missing.** `mvn dependency-check` was promised with Dependabot but never added. OWASP `dependency-check-maven` now lives in a `security` Maven profile (out of the default build — the NVD feed is slow); a `dependency-check` CI job runs `-Psecurity dependency-check:check` and gates on CVSS >= 7, no-op until the `NVD_API_KEY` repo secret is set.

9. **Minor hygiene.** `LoggingAccountMailer` masks emails outside the local reveal path (first char + domain). Two shared files read `process.env.NODE_ENV` directly (would throw off-web); routed through `platform/isDevEnvironment` (typeof-guarded). The privacy page's sub-processor list was missing Fly.io (API host) — added.

## Not fixed (accepted, logged as debt)

- **Per-instance rate buckets + OAuth session.** Fine while Fly runs one machine (`min_machines_running = 1`); a landmine only if someone scales out without reading 1.5/1.8. Same class as the WS registry — documented single-instance, interface-seamed where it matters.
- **Apple refresh token stored plaintext** on `accounts.refresh_token` — a disclosed, deliberate exception for TN3194 revocation on account deletion, not a regression; the blanket "provider tokens are never stored" claim is the stale wording, not the code.
- **Golden corpus tests write mechanics, not diff parity** (Java applies the client's diff verbatim; there is no server-side compare to test). With the TS capture tooling deleted at 1.13, a future regen is Java-testing-Java — a real gap, but one the cutover (2.6) is the place to address, not here.
- **Bootstrap snapshot-consistency** rests on Hibernate connection-timing defaults and has no concurrent-write test. Low risk; revisit if a torn read ever surfaces.
